# 不务正豆 · 幸运抽奖

面向店内安卓平板与手机的离线抽奖 PWA。紫色像素游戏风，无顾客账号、无服务器数据库、无外部字体或 CDN 资源。

## 启动与安装

- 线上：打开 GitHub Pages 地址（发布后填入下方），等待页脚出现 **离线已就绪**。
- 安卓 Chrome：菜单 → **添加到主屏幕 / 安装应用**，按提示安装。若没有安装项，请更新 Chrome，并确认使用 HTTPS。
- 首次打开需要网络，缓存完成后可断网抽奖。未曾打开过的新设备不能第一次就离线运行。
- 平板支持横屏，手机支持竖屏；允许系统自由旋转。
- 数据管理 → 申请持久存储，可减少浏览器在空间不足时自动回收数据的风险；是否批准由浏览器决定。

本地预览（需 Node.js 24 或更新版本）：

```powershell
npm ci
npm start
```

在这台电脑打开 `http://localhost:4173`。不要直接双击 `dist/index.html`。局域网普通 HTTP 地址可用于布局预览，但安卓 PWA 安装和 Service Worker 需要 HTTPS；正式使用 GitHub Pages 地址。

## 店内操作

1. 老板先在“奖池设置”填写十种奖项的概率与库存，确认保存。
2. 顾客点击“开始抽奖”，等待结果，然后选择“确认领取”或“放弃”。
3. 确认领取：正式写入记录，消耗总/月/日库存。放弃：资格作废，不扣库存、不写中奖记录。
4. 本轮结束后，“开始抽奖”会被“老板操作 · 下一位顾客”替代，刷新也保持此状态。老板交接给下一位后确认继续。
5. 没有识别人身份的功能，老板必须现场监督。下一位按钮是操作确认，不是身份验证；请勿让同一顾客自行交接重抽。

中奖后页面意外关闭，重开会显示同一份待领取结果。确认后的记录不会因刷新重复发放。若领取失败，页面会提示原因，不能超库存发奖。

折扣与立减仅针对体验费，不折现、不找零、不与其他优惠叠加。

## 概率与库存规则

默认值：9折 20%、8折 10%、7折 5%、6折 16%、5折 2%、减3元 5%、减2元 15%、减1元 25%、时段卡 1.5%、全天卡 0.5%。

- 十种配置概率合计必须等于 100%。支持小数，0% 表示暂停。
- 三个库存输入留空表示不限；0 表示暂停。
- 总库存指 **累计发放上限**，不会自动重置。例：总库存 10、累计已领 4，则剩余 6。补货 5 份，应把总库存由 10 改为 15。
- 月上限和日上限分别按 **北京时间 Asia/Shanghai 的自然月、自然日**计算，不是过去 30 天或 24 小时。
- 总/月/日三个限制同时生效，任一个用尽即暂停该奖项。可用奖项按原有配置比例归一化。全部暂停时不能开始抽奖。
- 保存设置不会修改历史记录或返还库存。设置不能在一轮待领取期间更改。
- 恢复默认奖池：恢复默认概率，并把所有库存限制设为不限；**保留历史、库存流水与累计发放数量**。
- 如果把总库存设为小于累计已发放数，该奖项会暂停，剩余显示 0。

库存看板的“初始总库存 / 当前总上限”展示当前配置的总量，配置更改前后的数值会保存在变更记录里。

## 中奖查询

仅收录确认领取的数据，按领取时间从早到晚排序；可选择折扣、立减、体验卡类别和历史日期。默认跟随今天，跨天自动切换；主动选择历史日期后不会强制跳回今天。

## 测试模式

奖池设置 → 进入测试模式。黄色横幅会持续提示。

- 测试奖池、库存、流水和中奖记录独立存在 `sandbox` 数据分区。
- 测试抽奖页可指定任一奖项，也可随机抽取；指定奖项仍遵守测试库存限制。
- 修改测试库存为 1，领取一次后验证耗尽；设为 0 验证暂停。测试概率和库存的保存不会修改正式设置。
- 可以验证确认、放弃、交接流程。测试数据不会出现在正式中奖查询里。
- 退出测试后才会使用正式数据。重置测试数据只影响测试分区。
- 测试模式下禁用正式数据的导入、导出、恢复与清空按钮。

## 备份与迁移

数据管理 → 导出完整 JSON，建议每日营业结束后备份。导出包含概率/库存配置、中奖记录、库存流水、设置变更记录和更新时间，不包含顾客个人信息。

导入时先检查格式、版本、奖项、时间、重复记录与流水对应关系，显示摘要后再确认替换。单文件上限 20MB。**导入是整份替换，不是合并或同步**，建议先导出当前数据。导入不会恢复可领取的待决抽奖。

不同设备、不同浏览器、不同站点域名/地址的数据不会自动同步。迁移设备时：旧设备导出 → 新设备导入 → 核对库存 → 停用旧设备。不能将同一份库存复制到多台设备同时发放；导入较旧备份会回滚到旧库存状态。

清空历史中奖记录需要两次确认，第二次输入“清空”。该操作只删除查询记录，**不删除独立库存流水、不返还库存**。完整历史只有导入备份才能恢复。

浏览器 IndexedDB 是本机持久存储，并非云备份。普通关闭/刷新不丢失数据；清除站点数据、隐私模式结束、设备损坏或浏览器回收空间可能造成丢失，因此必须定期备份。

## GitHub Pages 部署

所有运行文件位于 `dist/`，路径均为相对路径，兼容 `https://用户名.github.io/仓库名/` 子目录。

1. 创建 GitHub 仓库并上传完整项目，默认分支 `main`。
2. 仓库 **Settings → Pages → Build and deployment → Source → GitHub Actions**。
3. 推送后，`.github/workflows/pages.yml` 会执行领域测试和 Chromium 浏览器测试，再上传 `dist` 并发布。
4. 在 Actions 查看结果，访问 `github-pages` 部署地址即可。

GitHub 官方配置文档：https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

网页无登录要求。Pages 只托管公共程序文件，**本机中奖记录和库存不会上传到 GitHub**。源码中不要加入备份 JSON。GitHub Pages 的首次访问速度取决于店内网络；完成缓存后离线运行不受影响。

更新时务必修改 `dist/sw.js` 中的缓存版本，例如从 `bean-shell-v1.0.0` 改为 `bean-shell-v1.0.1`，并发布完整一组文件。新版本缓存完成后会等待旧页面关闭，再激活，避免抽奖过程中切换代码。更新前请备份，关闭所有已打开的应用窗口后联网重开。更新不清除 IndexedDB 数据。

## 技术结构与验证

```text
dist/engine.js       纯领域逻辑、概率、周期、库存、备份校验
dist/storage.js      IndexedDB 事务存储适配器
dist/app.js          五个功能页面与交互
dist/style.css       响应式像素风布局
dist/sw.js           无外部依赖的离线应用壳缓存
dist/manifest.webmanifest  PWA 安装配置
tests/engine.test.mjs      库存与抽奖规则测试
tests/browser/            浏览器交互、离线、并发和持久化验证
```

一次领取事务同时写入唯一抽奖 ID、库存流水、中奖记录及会话状态，在事务 `complete` 后才显示领取成功。支持时请求 IndexedDB `strict` 耐久性。多页面共享数据库事务，同一抽奖重复确认幂等；设置版本校验阻止并发覆盖。

为后续同步保留 `repository.read/execute/replace` 适配边界。接入多设备服务器时应由服务器统一分配抽奖 ID、串行检查库存、幂等领取，并处理离线冲突；不能仅把本地 JSON 互相覆盖。

```powershell
npm test
npx playwright install chromium
npm run test:browser
```

浏览器测试使用桌面 Chromium 和安卓尺寸/触摸模拟，不替代真实安卓硬件验收。交付时应在店内实际平板/手机上再检查安装、离线重开、触摸与下载备份。详细已执行结果见 `验收报告.md`。
