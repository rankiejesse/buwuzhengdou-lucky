# 不务正豆工作台

面向店内安卓平板与手机的轻量抽奖系统。提供独立离线APK和浏览器PWA；紫色像素游戏风，无顾客账号、无外部字体或CDN。

## 安装使用

- [独立安卓APK v1.3.0](https://github.com/rankiejesse/buwuzhengdou-lucky/releases/download/android-v1.3.0/buwuzhengdou-workbench-1.3.0.apk)
- [安卓安装、升级与迁移说明](安卓应用使用说明.md)
- [网页版](https://rankiejesse.github.io/buwuzhengdou-lucky/)
- [浏览器兼容入口](https://rankiejesse.github.io/buwuzhengdou-lucky/repair.html?mode=browser)

APK桌面名称为“不务正豆工作台”，资源内置，首次启动即可离线，不依赖Chrome安装壳。由1.1.0升级时直接覆盖安装，保持同一应用和签名，不要先卸载。网页和APK分别保存自己的数据，跨环境请用JSON迁移。

PWA首次联网加载，等待“离线已就绪”后可从安卓Chrome安装。若Chrome安装版在系统图标处停留，可改用独立APK或浏览器兼容入口；原启动壳故障尚无该设备的确切诊断。

## v1.3.0 工作台

保留抽奖为默认首页，升级显示名称，不改变应用ID `com.buwuzhengdou.lucky` 或签名；直接覆盖安装保留已有数据。

- 每日收支记录初始现金、剩余现金、微信和支付宝收入。现金变化＝剩余－初始；当天增值＝现金变化＋微信＋支付宝。总/月/年收入按登记日期汇总增值（未扣预算支出）。一天一条，允许负增值；金额使用整数分计算。
- 初次登记自动记录时间，编辑金额保留登记时间和首次创建时间。日历可主动改登记时间，不能选未来或已有登记的日期。可按月份查询历史。
- 预算小本支持固定金额或本月/本年/总收入的百分比（最多两位小数）。采用老板选择的规则：收入×比例－其他所有预算本在所选期间的实际支出＝当前额度；再分别减本子自己的计划或实际支出。
- 未购买项按拟购金额计计划余额；已购买项改按实际金额计计划余额，避免重复扣减。标记实购会打开金额确认表单。只有实际支出才影响其他本子，撤销实购或确认删除会重新计算。
- 月/年百分比本按当前自然月/年统计支出；历史已购物品仍保留可查，新周期不再扣旧周期实购，尚未购买计划继续保留。固定及总收入本按累计支出。多个本子的可用额度不应相加当现金。
- 收支记录、预算本、待办支持左滑垃圾桶并确认删除；类别删除同样需确认。桌面悬停或键盘聚焦可访问删除按钮。
- 设置语言默认中文，不随英语平板改变；可选择跟随系统（英语界面，其余语言回退中文）。安卓应用内日期选择器也使用所选语言配置。
- 全部收支/预算进入JSON完整备份。导入替换抽奖、收支、预算，并明确提示旧版备份没有收支预算会清空这部分；密码及答案仍不进入备份。清除“抽奖数据”保留收支预算，删除收支/预算在对应页面确认进行。
- IndexedDB升级到版本3，关闭/拒绝旧代码连接，以防旧版抽奖清除流程丢掉收支；原抽奖状态和安全设置保留。

## v1.2.0 周库存与安全设置

- 原总库存改为周库存；旧数值自动转为每周上限，全部历史及领取流水保留。
- 周库存按北京时间每周一00:00重置；月上限按每月1日00:00、日上限按每日00:00计算。
- 手动临时补货可追加本周或本月额度，到下一次对应周期重置时失效。只增加所选周期，其他限制继续生效，不改变基础配置。
- 修改概率与周/月/日库存前验证老板密码。补货、撤销补货、恢复默认和导入奖池也验证密码。
- 设置里首次创建密码及1至5个自定义安全问题。忘记密码时任选已设置的一题，答对后重置。修改问题需要当前密码。
- 设置中“清除抽奖数据”只需一次确认：清空正式与测试的记录、库存流水、临时补货及会话，领取计数归零；保留奖池配置、密码、安全问题。

## 抽奖规则

默认十种奖项：9折20%、8折10%、7折5%、6折16%、5折2%、减3元5%、减2元15%、减1元25%、时段卡一张1.5%、全天卡一张0.5%。只保留这十种，配置概率合计必须100%，支持小数。

顾客点击开始 → 动画 → 确认领取或放弃。只有确认领取才写正式记录和库存流水。放弃不扣库存、不记正式中奖记录，资格已使用；刷新保持结果，老板确认“下一位顾客”后才可继续。由老板现场监督身份与次数。

周/月/日三层限制同时生效，留空不限，0表示该层无基础额度。临时额度可追加到所选周/月层；日上限不被补货绕过。库存暂停的奖项自动退出，其余概率按配置比例归一化，全部不可用时暂停抽奖。

库存看板展示基础周库存、累计领取、本周已领/有效周上限、本周剩余、本月及今日领取、周/月临时额度和可抽状态。累计领取仅作历史统计，不再是库存上限。

折扣与立减仅针对体验费，不折现、不找零，不与其他优惠叠加。

## 密码与安全问题

首次进入设置由老板自行创建密码，没有默认密码。密码4至64位；安全问题1至5组，问题自定义、答案必填。答案不区分英文大小写、首尾空格，并做全角半角规范化。

解锁仅用于本次修改，最多15分钟；保存或离开页面后锁定。一次授权只能提交一次受保护操作，安全设置变化后旧授权失效。连续错误5次后暂锁30秒，重新打开仍保留等待状态。

密码与答案使用独立随机盐及PBKDF2-SHA256（600000次）保存校验值，不存明文。安全设置单独保存在当前设备的存储中，**不随JSON导出或导入替换**；新设备须设置自己的密码。清除抽奖数据不清除密码，不能通过清除业务记录解除密码保护。它是离线老板操作保护，不是联网身份系统。

## 记录、测试与备份

中奖查询只含已确认领取的记录，按时间升序，可选类别和历史日期；默认跟随当天，跨天自动切换。周期统一用北京时间Asia/Shanghai。

测试模式的奖池、临时补货、库存流水和中奖记录使用独立分区，可指定奖项验证动画与库存逻辑；修改测试概率/库存同样需要老板密码，不影响正式数据。

数据管理导出JSON v2，包含设置、领取记录、库存流水、临时补货与变更记录。支持导入原v1备份，并自动把总库存转为周库存。导入为整份替换，需要密码和确认，不自动合并；旧备份可能回滚库存。单文件上限20MB。待领取资格不通过备份恢复。

数据管理中的“清空历史中奖记录”只删除查询记录，保留库存消耗；设置里的“清除抽奖数据”连库存流水、临时补货及领取计数一起重置。两者均只确认一次，区别在操作说明中明确展示。

数据仅保存在本机，不跨设备同步。日常关闭、刷新、正常覆盖升级会保留；卸载、清除站点/应用数据、损坏可能丢失，请每日营业后导出。迁移时导出旧设备 → 新设备导入 → 核对库存 → 停止在旧设备同时发奖。

## 本地开发与验证

Node.js24：

```powershell
npm ci
npm start
npm test
npx playwright install chromium
npm run test:browser
```

预览地址 http://localhost:4173。不要直接双击HTML。正式PWA使用HTTPS；APK无须网络。启动与浏览器测试会自动执行构建，把样式、应用与启动帮助打包到单个HTML，避免冷启动等待外部脚本。

独立安卓打包：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build-android.ps1 -IncludeTests
```

需JDK17、Android SDK36/Build Tools36、Gradle8.13。脚本使用ASCII临时工程路径规避Windows中文路径限制。私有签名位于用户目录的.codex/app-signing/buwuzhengdou，不在仓库中；升级必须沿用原签名。

## 文件结构

```text
dist/engine.js       领取、周/月/日库存、临时补货、版本迁移与备份校验
dist/auth.js         密码/答案PBKDF2校验
dist/storage.js      IndexedDB事务、单次授权、安全设置与原子清除
dist/app.js          五个页面与老板操作界面
src/index.html       启动模板
scripts/build.mjs    自包含HTML构建
android/             独立安卓应用与设备级测试
scripts/prepare-android.mjs   安卓本地资源准备
scripts/build-android.ps1    APK打包
```

业务记录与库存领取在同一IndexedDB严格事务中提交。保留原数据库名与业务键，schema1自动迁移到schema2，不删除历史。数据库版本提升到2，关闭旧版连接，防止旧缓存程序绕过新密码校验。安全设置另键存储，密码变更和受保护操作在事务中核对版本，防止旧授权与并发覆盖。

repository的read/execute/replace保留将来接入同步服务的边界。多设备同步须由服务端统一分配ID、原子检查库存和幂等发放，不能互相覆盖本机JSON。

## GitHub Pages 发布

Settings → Pages → Source选择GitHub Actions。推送main后工作流执行领域及浏览器测试，再发布dist。使用相对路径兼容仓库子目录。[官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

更新时提升dist/sw.js的缓存版本并执行npm run build。正常更新等待旧页面关闭再激活；启动帮助页可由老板主动更新。更新前备份，不清除本机数据库。Pages仅托管程序，不上传本机记录或密码。APK资源随APK更新，不从网站自动更新。

详细验证范围见《验收报告.md》。
